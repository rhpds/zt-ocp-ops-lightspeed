= OpenShift Lightspeed Lab

Showroom content for a standalone OpenShift Lightspeed lab, extracted from module 13 of the OpenShift Ops Day Roadshow.

== Lab Content

* link:content/modules/ROOT/pages/index.adoc[Lab Setup] — console access, terminal access, and prerequisites.
* link:content/modules/ROOT/pages/13-openshift-lightspeed.adoc[OpenShift Lightspeed] — configure an LLM provider, explore the assistant, generate YAML, troubleshoot a demo pod, and clean up.

Allow 20-30 minutes for the lab. Navigation is unconditional; no module selection flags are required. The original `13-openshift-lightspeed.adoc` filename is retained.

== Environment Requirements

The environment provisioning must supply:

* An OpenShift cluster with administrator access and an installed OpenShift Lightspeed Operator in `openshift-lightspeed`.
* An `azure-api-keys` secret in `openshift-lightspeed` with credentials for the configured Azure OpenAI endpoint and `gpt-4` deployment/model.
* Network access from the cluster to the LLM endpoint.
* The Showroom console tab and wetty terminal service, with `oc` and `jq` available.

The lab creates its own intentionally unschedulable pod in `lightspeed-demo`; it does not depend on another roadshow module to deploy the demo. Cluster and operator provisioning are managed outside this content repository.

== Showroom Configuration

The Antora component name is `zt-ocp-ops-lightspeed` in link:content/antora.yml[content/antora.yml], both playbooks, and link:ui-config.yml[ui-config.yml].

The workspace opens in split view with three tabs:

* *OCP Console* — `https://console-openshift-console.${DOMAIN}`.
* *Terminal* — `/wetty`, port `443`, used by executable command blocks.
* *Terminal 2* — `/wetty`, port `443`, for monitoring commands.

The Showroom deployment must resolve `DOMAIN` to the cluster's application route domain and supply these AsciiDoc attributes:

* `openshift_cluster_console_url`
* `openshift_cluster_admin_username`
* `openshift_cluster_admin_password`

`content/antora.yml` includes example connection details for static previews. Runtime deployment must override them with the actual lab values. The `ols_azure_url` attribute supplies the Azure OpenAI endpoint used in the exercise and can also be overridden.

`site.yml` builds into `www/`; `default-site.yml` builds into `public/`. Both use the same theme and supplemental UI. A static Antora preview renders the instructions; live console and terminal tabs require the Showroom runtime and its terminal service.

== Local Development

With Antora installed, build the instructions:

[source,sh]
----
./local-build/build.sh
----

To build and serve with Podman:

[source,sh]
----
./local-build/up.sh
----

Open http://localhost:8080/index.html.

[cols="1,2"]
|===
|Command |Purpose
|`./local-build/build.sh` |Generate the static site using `site.yml`.
|`./local-build/serve.sh` |Serve the generated site with Podman.
|`./local-build/stop.sh` |Stop the preview container.
|`./local-build/reset.sh` |Stop, rebuild, and serve again.
|`./local-build/status.sh` |Show preview container status.
|===

Optional environment variables:

* `SHOWROOM_PORT` — host port (default `8080`).
* `SHOWROOM_PULL=1` — pull the httpd image before starting.
* `SHOWROOM_SITE_YML` — alternate Antora playbook (default `site.yml`).
* `SHOWROOM_WWW` — absolute build and preview directory (default `www/` in this repo).
* `SHOWROOM_CONTAINER_NAME` — preview container name (default `zt-ocp-ops-lightspeed-httpd`).

To validate both playbooks directly:

[source,sh]
----
antora generate site.yml --stacktrace --log-failure-level=warn
antora generate default-site.yml --stacktrace --log-failure-level=warn
----
